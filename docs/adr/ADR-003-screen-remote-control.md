# ADR-003: Удаленное управление экраном Android с macOS (Screen Mirroring & Remote Input)

## Статус
**Принято (Accepted)**

## Контекст
Одна из ключевых функций экосистемы AndroMac — возможность просматривать экран телефона в реальном времени на Mac и управлять им с помощью трекпада, мыши и клавиатуры без требования наличия Root-прав на Android.

Существуют два фундаментальных пути реализации:
1. **Путь через публичные API Android (MediaProjection + AccessibilityService):**
   - *Плюсы:* Не требует режима разработчика или отладки.
   - *Минусы:* Диалог согласия пользователя при каждом запуске сессии; лаги и повышенная нагрузка на CPU; невозможность плавной прокрутки и быстрых жестов; черные экраны на окнах с `FLAG_SECURE`; высокий риск отклонения в Google Play из-за злоупотребления Accessibility.
2. **Путь через adb + scrcpy-server:**
   - *Плюсы:* Аппаратное кодирование H.264/H.265 с минимальной задержкой (30–60 FPS, < 50 мс); полная эмуляция касаний, кликов мыши, колеса скролла, клавиатуры и физических кнопок (Back, Home, Recents, Volume, Power); отсутствие всплывающих окон согласия при каждом запуске; надежность, проверенная миллионами пользователей.
   - *Минусы:* Требуется однократное включение «Отладки по Wi-Fi» (Wireless debugging на Android 11+) или подключение по кабелю.

## Решение

Принята двухэтапная стратегия на базе **adb + scrcpy-server**:

### Этап 1 (MVP): Встроенные бинарники и протокол нормализованных координат
- macOS-приложение включает в состав дистрибутива автономный легковесный бинарник `adb` и файл `scrcpy-server.jar` (лицензия Apache-2.0).
- Подключение выполняется через Wireless Debugging (сопряжение по коду и порту) либо через автоматический проброс портов `adb forward / reverse`.
- Модель событий ввода `RemoteInputEvent` стандартизирует координаты в нормализованном диапазоне `[0.0, 1.0]`:
  - `RemoteInputType.touchDown`, `touchMove`, `touchUp` с относительными координатами `xRatio`, `yRatio`.
  - Эмуляция нажатия физических кнопок через `AndroidNavButton` (`back`, `home`, `recents`, `volumeUp`, `volumeDown`, `power`).
  - Текстовый ввод через `textInject`.

### Этап 2: Встраивание потока в окно Flutter через VideoToolbox
- Для устранения отдельного окна SDL поток H.264 с сокета `scrcpy` принимается Swift-модулем на macOS.
- Нативное декодирование через фреймворк Apple **VideoToolbox** (`VTDecompressionSession`) преобразует фреймы в аппаратные `CVPixelBuffer`.
- Фреймы отдаются во Flutter Engine как нативная текстура (`FlutterTextureRegistry`), обеспечивая бесшовный рендеринг внутри окна AndroMac с поддержкой оконных эффектов macOS.

## Последствия

### Положительные:
- Высочайшая производительность потокового видео (60 кадров/с, битрейт до 8 Мбит/с, аппаратный декодер).
- Отсутствие Root-прав.
- Полная поддержка клавиатурных сокращений, перетаскивания и жестов скролла трекпадом Mac.

### Отрицательные:
- Для первоначальной активации пользователю необходимо включить «Режим разработчика» и «Отладку по Wi-Fi» в настройках Android (поддерживается пошаговым мастером онбординга).
